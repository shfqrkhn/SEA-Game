# Candidate security review — partial

2026-10-08, W08/W25, D08, M6, T12/T18. This is local engineering evidence, not release/security/rights acceptance.

The build emits an early meta CSP in each standalone file. Only the SHA-256 digest of its exact LF-normalized bundled script is permitted by script-src; script-src-attr is none. default-src, connect-src, object-src, base-uri and form-action are none. img-src permits the document origin, file resources for optional local artwork, and the established HTTPS artwork prefix. style-src retains unsafe-inline because the current UI uses inline SVG/HTML styles and DOM style updates. This permits inline styling and is a documented residual surface. The policy does not establish confidentiality from other same-origin code or users editing local files.

Artwork now uses idempotently registered capture listeners. Targets must be connected IMG nodes with a canonical known artwork identity. A remote failure retries only its canonical local path; a local failure removes the optional raster and leaves the vector. Offline/file routes never retry remotely. Production callbacks are tested with event/DOM models, not an actual browser.

Templates reject executable event attributes; the script bundle rejects a closing script tag. Build inputs normalize CRLF/CR to LF and trim trailing template whitespace. Generated-file tests recompute the actual emitted script digest, require a single script and policy placement before resources, and demonstrate digest invalidation after a one-byte change. These checks prove artifact consistency; they do not prove browser enforcement.

Hash and event-listener decisions follow [MDN script-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src). Meta policies have limitations described in [MDN CSP guide](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP); frame-ancestors, reporting and sandbox acceptance are not claimed here. A future hosting policy must be reviewed with the actual deployment configuration.

Required before acceptance: run both exact candidate files under the supported HTTPS and file/offline browser environments; verify initial application execution, EN/FR phase controls, optional image success/failure, backup download/import/restore, storage recovery and CSP console/network violations. Test injected inline handlers, unauthorized scripts and connections in an authorized qualification environment. Qualify style/rendering, redirects and hosted header interactions. The Codex built-in browser currently cannot access local candidate files/localhost, and no HTTPS candidate URL exists; these checks stay OPEN under the user's instruction.

Full untrusted-data/DOM/network review, distribution permissions/root licensing, independent security review and classroom acceptance remain OPEN. No rights are inferred from a public repository. Candidate remains uncommitted and undeployed; no PRODUCT_RELEASE assurance pass is counted.
